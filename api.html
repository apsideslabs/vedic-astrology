API and command line

The chart page runs the engine in your browser. The same engine also ships as a Python package with a FastAPI service — clone the repository and run it locally.

Run it

git clone https://github.com/apsideslabs/vedic-astrology.git
cd vedic-astrology
pip install -r requirements.txt

# web app
uvicorn app.main:app --reload          # http://127.0.0.1:8000
                                       # interactive docs at /docs

# command line
python -m jyotish.cli --date 1990-04-14 --time 08:15 \
    --lat 13.0827 --lon 80.2707 --tz 5.5 --place Chennai

# tests
python -m pytest tests -q

POST /api/chart

Takes birth data, returns the whole chart as JSON.

{
  "date": "1990-04-14",
  "time": "08:15",
  "latitude": 13.0827,
  "longitude": 80.2707,
  "tz_offset": 5.5,
  "place": "Chennai",
  "name": "",
  "ayanamsa": "lahiri",        // or "raman_397"
  "house_system": "whole_sign" // or "sripati", "equal"
}

The response contains:

  • birth — local time, UT, Julian Day, coordinates
  • ayanamsa — model, value in degrees, formatted
  • lagna — sidereal degree, sign, nakshatra, pada, navamsa, lord
  • planets — nine grahas with sign, degree, nakshatra, pada, navamsa, house, dignity, combustion, retrogression, strength breakdown
  • houses — twelve bhavas with sign, lord, where the lord sits, occupants, cusps, significations
  • panchanga — vara, tithi, yoga, karana
  • vimshottari — the full timeline with bhuktis and the current period
  • yogas — every yoga the engine knows, present or not
  • aspects and aspects_by_house — planet-to-planet and house aspects with sight fractions
  • transits — gochara from the Janma Rasi, with Sade Sati state
  • interpretation — sections of statements, each with {rule, text, source}

GET /api/health

Engine version, ephemeris version, and the ayanamsas and house systems on offer.

Library use

from jyotish import BirthData, build_chart
from jyotish import interpret, transits

birth = BirthData(
    date="1990-04-14", time="08:15",
    latitude=13.0827, longitude=80.2707,
    tz_offset=5.5, place="Chennai",
)
chart = build_chart(birth, ayanamsa="lahiri", house_system="whole_sign")

chart.lagna_sign                    # 'Taurus'
chart.planets["Moon"].dignity       # 'debilitated'
chart.vimshottari["current"]        # the running mahadasha and bhukti

reading = interpret.interpret(chart, transits.analyse(chart))
for section in reading["sections"]:
    for s in section["statements"]:
        print(s["rule"], "|", s["source"], "|", s["text"][:80])

The stack

LayerChoiceWhy
Ephemerisastronomy-engine pure Python and JS, no data files, ~1′ accuracy, MIT
WebFastAPI + Uvicorn typed request models, automatic validation, OpenAPI
ValidationPydantic v2range and format checks on every input
TemplatesJinja2server-rendered shell, no build step
Testspytest + httpx34 tests, including the book's worked example

On the ephemeris: the industry standard is the Swiss Ephemeris (pyswisseph), which is what commercial packages use and which implements about forty ayanamsas natively. It is a C extension. ephemeris.py is deliberately a thin adapter — it returns {planet: {longitude, latitude, speed}} and nothing else — so swapping in pyswisseph is a one-function change with no effect on the rest of the engine.
